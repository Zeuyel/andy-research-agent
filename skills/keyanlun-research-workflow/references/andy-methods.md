> 状态：历史候选方法摘要，仅作检索导航，不再整体标为“已采用”。1,874条是机器组织范围，非全文阅读完成量。旧分析已有写作顺序、机制优先等误归因及不存在的来源ID，引用前必须回读原文。优先用 `skills/andy-research-agent/references/source-backed-rules.md` 的18条局部核对规则，并查 `final/evaluation/regression-report.md`。下文保留作审计历史，不能据此声称“Andy如此说”或“所有资源已吸收”。

## 使用规则

- 当任务涉及“科研论/Andy 的方法”时，按任务加载本模块的 1–3 节，不默认把全部观点当作答案。
- 先判断这是跨案例重复的工作流规则，还是针对某个学科/个人情境的建议。前者可作为候选流程，后者必须回到原始证据和用户约束。
- 每次应用都产出可检查的中间物：目标卡、检索日志、分组表、证据卡、最小验证计划、素材卡或决策表。
- 具体科学结论仍以论文、实验、数据和正式制度为准；Andy 的经验不能替代同行评审证据。

## 1. 以终为始：把“学习”改写成交付目标

**触发**：不知道学什么、选题发散、毕业/基金/就业临近、同时追很多方向。

**规则**：科研动作不以“读完、学会软件、做过课程”为终点，而以可观察交付物为终点：可投稿稿件、最小验证、基金本子、可复现代码、专利/数据集或可呈现的真实成果。

**操作**：

1. 写出目标去向、期限、硬门槛、资源和不可接受风险。
2. 把目标转成一个最小交付物和完成判据。
3. 比较候选动作对交付物的贡献、完成概率和机会成本。
4. 先闭环一个最高杠杆动作，再扩展技能和支线。

**边界**：成果导向不等于牺牲学术诚信、健康、安全或长期能力；毕业规则、作者贡献和项目政策要另行核实。

**代表来源**：`1525825511148522`（2025-01-29）、`5121825828228424`（2025-01-28）、`4844152224284248`（2024-08-24）。

## 2. “搜—聚—分—验—合”：从模糊方向到可行问题

**触发**：导师只给大方向、读了很多论文仍没有选题、研究内容过散、需要搭建博士论文/基金主线。

**规则**：不要把找选题、做实验和写论文混成一步。先定义现实问题或异常现象，再宽检索建立领域地图，聚类/分组识别缺口和矛盾，做最小验证，最后合成论文或计划书。

**操作**：

1. 把对象、场景、痛点、变量、约束和预期产出写具体。
2. 用宽词找到样本，允许跨领域寻找同构问题。
3. 按问题、对象、方法、变量、性能、机制和缺口分组。
4. 对候选题写出关键假设、必要证据和最低成功标准。
5. 先验证资源/方法/指标是否可得，再扩展完整实验和叙事。
6. 用验证结果反向修正检索式、分组和主线。

**边界**：分类不是目的；“换材料/拼模块”不自动等于创新；文献先例只能证明可行性线索。

**代表来源**：`211228154851541`（2023-10-30）、`411558142888488`（2023-10-30）、`588125555484554`（2023-07-29）。

## 3. 钓鱼式检索：从线索持续扩展，而不是执着一个词

**触发**：结果太少/太多、一词多义、找不到实验细节、想找源码/数据/复现资源。

**规则**：从种子文献或真实案例出发，沿同义词、上下位词、参考文献、被引、作者/课题组、正文、补充材料、代码和数据集扩展。检索结果只是线索，不是质量证明。

**操作**：

1. 从对象、过程/机制、方法/测量、场景/限制建立词表。
2. 先在标题/摘要中用约束词提高相关性，再按需要扩展到全文。
3. 从高相关样本抽取作者术语、实验动作、评价指标和失败条件。
4. 沿引用网络、作者、Google Scholar/WoS/Scopus、GitHub、Papers with Code 等入口交叉搜索。
5. 记录命中、漏检、排除原因和下一轮词表；检索到足够支撑当前子问题的证据后停止扩张。

**边界**：过度精确会漏检，过度宽泛会增加筛选负担；必须去重、核对全文和权限；不能把搜索摘要当原文。

**代表来源**：`1525825454525182`（2025-01-29）、`1525825288548422`（2025-01-28）、`4848242184582128`（2024-12-03）、`811228555422252`（2023-10-27）。

## 4. 鲸吞—聚类—分组：先有领域地图，再收敛

**触发**：文献海量、分组后没有 idea、担心少量样本代表全貌。

**规则**：先设定样本边界并获得足够宽的视野，再识别高频、异常、空白和矛盾组；分组服务于当前问题，不是为了制造标签。

**操作**：

1. 明确纳入/排除标准和样本边界。
2. 粗分后找趋势、trade-off、冲突和未解决问题。
3. 对与任务最相关的组二次分组，保留未分类项。
4. 从组内提取变量、方法、性能和证据缺口。
5. 用缺口更新检索式，必要时做第二轮采集。

**边界**：鲸吞不是下载和通读全部论文；抽样必须有合理边界，分组不能替代实验。

**代表来源**：`4844152224284248`（2024-08-24）、`5121518154155514`（2024-10-12）、`2858455114254541`（2024-11-20）。

## 5. 素材库与证据卡：把文献变成可写资产

**触发**：读了很多却不会写、图片和文字脱节、综述变成流水账、段落无法追溯。

**规则**：图片、前言/文字、方法和证据分别组织；素材库的目标是支撑目标稿件的主张和图表，不是收集最多 PDF。

**最小记录**：

`主张 | 证据/图表 | 来源与定位 | 解释 | 限制 | 拟放位置 | 核查状态`

**操作**：

1. 先定义目标稿件要回答的主张和图表结构。
2. 用标题/摘要快速筛选能直接支撑论点的文献。
3. 按问题、材料/体系、结构、性能、机制、方法和边界加短标签。
4. 把“问题—已有方案—缺口—本文贡献”组织成证据链。
5. 写作时用素材卡重组自己的叙述，保留 DOI、页码、图号和版本。

**边界**：素材库不是复制原句、图片或数据；进入成文后按增量补缺，不无限返工；版权和引用规范必须保留。

**代表来源**：`2858152828881811`（2025-01-23）、`4848581881155858`（2024-10-12）、`1522141552825412`（2024-06-28）。

## 6. 证据与机制优先：从“性能好”走向可检验解释

**触发**：只有指标提升、没有最优样品、被要求补机理、存在性能 trade-off。

**规则**：区分观测事实、机制推断和待验证假设。每个解释都要对应可证伪预测、对照、表征或模型，不用一张图和“合理故事”替代机制证据。

**操作**：

1. 列出性能变化、控制变量和可能 trade-off。
2. 为每个机制假设写出“若为真，应观察到什么”。
3. 设计对照、时间点、结构/成分/失效前后表征或模型验证。
4. 把结构变化、机制证据、性能结果和边界条件对齐。
5. 写作中明确哪些是数据直接支持，哪些是推断，哪些仍待验证。

**边界**：指标提升不等于工程可用；模拟、表征和统计都要有适用边界；失败结果也应保留。

**代表来源**：`1525825454525182`（2025-01-29）、`5122428152885484`（2024-06-10）、`5121428285455484`（2024-12-02）。

## 7. “验”字诀：最小可行实验、复现与失败排查

**触发**：方案看起来有价值但没有数据、实验失败、代码/数据不可用、想大规模投入前评估可行性。

**规则**：把方案拆成 1–3 个必须成立的假设，先做信息增益最高、成本最低的验证。复现是可行性地基，不是研究终点。

**操作**：

1. 写出关键假设、最低成功标准和停止/转向条件。
2. 查找多个不同团队的相近成功案例，抽取参数交集。
3. 一次只改变一个关键变量，设置节点测试和排除法。
4. 记录样品/代码版本、输入、步骤、原始数据、处理过程、异常和环境。
5. 失败时先排查资源、输入、设备、边界条件、测量和代码，再决定修正、缩小或换题。
6. 验证通过后才扩展变量、样本和高水平叙事。

**边界**：一次复现成功不能证明普适；最小验证不等于省略关键对照、统计或伦理审查。

**代表来源**：`411558142888488`（2023-10-30）、`588551524284414`（2023-10-29）、`8858211214221582`（2024-11-14）。

## 8. 论文/综述/基金：让证据链服务于目标文本

**论文写作**：固定核心主张、证据链和目标期刊，再组织图表、结果讨论和段落；逐句检查结论是否有数据或引用支持。

**综述**：先确定边界、主线和分类维度，避免“按论文逐篇介绍”；把比较、矛盾、局限和未来问题写出来。

**基金**：先回答“为什么重要、哪里没解决、准备解决什么、为什么你能做”，再润色语言；素材数量服从立项逻辑，不要把多个低质量本子当买彩票。

**投稿/返修**：按证据强度、研究问题和期刊范围匹配投稿梯度；把审稿意见分类为原则性证据、解释澄清、结构表达、格式和超出范围，逐条记录行动和理由。

## 9. 论文主线、博士规划与职业决策

**规则**：论文、博士章节、基金和职业不是互不相关的任务；先明确 3–5 年目标和硬门槛，再比较成果的可迁移性、资源、概率、成本和不可逆风险。

**操作**：

1. 写出毕业/岗位的最低成果组合和时间节点。
2. 把核心问题拆成相互支撑的 2–4 个子问题，标出每篇论文的角色。
3. 区分保底成果、发展成果和高风险代表作，设置止损点。
4. 评估导师/团队时查看学生作者位置、毕业周期、去向、资源和指导方式，不只看头衔。
5. 面试或申请时用可验证成果证明能力：论文、专利、代码、数据、复现实验或真实应用，而不是只列“学过某软件”。

**边界**：论文数量、排名、海外经历或单个顶刊都不是充分条件；制度、行业周期、家庭约束和个人风险承受力必须纳入。

**代表来源**：`211228154858111`（2023-10-30）、`1525822155214582`（2025-01-17）、`82811522845411540`（2025-10-26）。

## 10. 导师沟通与执行系统

**规则**：不要只等待导师给答案，也不要把复杂冲突简化成情绪问题。带着结构化选项、证据、成本和需要对方做的具体决策沟通；把焦虑转换成下一步可观察动作。

**沟通模板**：

- 当前事实与已完成证据
- 方案 A/B（各自收益、成本、风险）
- 推荐方案及理由
- 需要导师确认的一个或两个决策
- 下一节点、交付物和复盘时间

**执行**：把任务拆成 15–60 分钟的可交付节点，优先硬 deadline 和阻塞项；记录会议结论、作者/资源约定和版本差异。高风险事项设置复盘点和停止规则。

**边界**：涉及霸凌、违规、署名、安全或持续心理症状时，使用学校/单位正式渠道和专业支持；方法论不能替代医疗或法律意见。

## 调用后的输出检查

每次用 Andy 方法回答具体任务，至少输出：

1. 当前任务卡和交付物；
2. 使用了哪一条方法及其适用边界；
3. 下一步动作和完成判据；
4. 需要补采或人工核验的证据；
5. 若是具体实验/论文结论，明确不能仅凭该模块下结论。

## 复核状态

- **已采用**：在多个年份/案例中重复且能转成行动步骤的工作流规则。
- **候选**：单个案例、强依赖个人背景或尚未完成原帖/评论复核的建议。
- **有冲突**：不同来源的适用条件未厘清；保留两种版本并回到原始证据。
- **已弃用**：被更新材料或更强证据否定的规则。
