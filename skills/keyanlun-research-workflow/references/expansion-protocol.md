# 增量吸收协议

## 目标

将「科研论」的存量目录、精华、帖子和文件转化为可复用方法，而不是复制原文。每一批资料都应能回答：它解决什么问题、在什么条件下有效、下一步要做什么。

## 单条知识记录

```text
主题：
触发：用户遇到什么任务时加载
问题：
方法/规则：
操作步骤：
输入：
输出：
失败模式与边界：
来源：星球/专栏/帖子/文件及定位
证据等级：A（直接可验证）/ B（间接支持）/ C（线索）
核查状态：候选 / 已核查 / 有冲突 / 已弃用
最后复核：YYYY-MM-DD
```

## 扩展循环

1. **采集**：先记录标题、主题、原始定位和可访问范围；不把搜索摘要当正文。
2. **抽取**：提炼问题、判断、步骤、产物和边界；删除故事性、重复性和无法行动的表述。
3. **交叉核对**：与现有核心规则和模块比较，标出重复、补充或冲突。
4. **落盘**：写入一个主题模块；来源和核查状态与方法放在同一条记录旁边。
5. **升级**：至少有一条直接来源并能通过一个具体任务验证后，才将状态改为“已采用”。
6. **索引**：更新 `module-registry.md` 的触发词、状态、来源和复核日期。
7. **回归检查**：运行模块检查脚本，确认 frontmatter、索引路径和必填字段完整。

## 冲突处理

不同来源的建议不一致时，保留两个版本及其适用条件；比较样本、任务目标、证据类型和失败成本。只有在证据足够时才合并，否则标记“有冲突/待复核”。

## 版权与隐私边界

只保存必要的短摘录、出处和自己的结构化总结；不批量复制受限帖子、付费文件或个人信息。无法确认权限时，保存方法摘要和定位，不保存全文。
